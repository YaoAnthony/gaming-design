# Climb

「起跳即爆炸」的房间制解谜平台游戏。Vite + React + TypeScript + Phaser 3 + Redux Toolkit + Ant Design（弹窗等界面组件）+ Motion（界面动画）。

## 线上版本

推到 `main` 后 GitHub Actions 自动打包部署到 GitHub Pages（`.github/workflows/pages.yml`）。线上只有游戏（正中一个「开始游戏」），没有编辑器；地图在本地编辑器里改，「写入 world.json」后 push。

## 命令

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器 http://localhost:5174
npm run build      # 类型检查 + 打包到 dist/
npm test           # vitest 单元测试
npm run lint       # ESLint（CI 里和测试一起跑）
npm run gen-art    # 重新生成占位 PNG 美术到 src/asset/（会覆盖同名文件；后面跟文件名就只生成那几张）
npm run desktop    # 打包后用 Electron 打开桌面版；desktop:dev 连开发服务器（见 docs/desktop.md）
```

## 多语言

`i18next` + `react-i18next`，入口 `src/i18n/index.ts`，文案在 `src/i18n/en.json` / `zh.json`。默认英文，标题页右上角切换，选过的跟着玩家存档（`save`）一起存；`setLang('zh')` 切换。玩家看得到的文字都走翻译：界面用 `t()`；游戏代码里的飘字、死亡原因、NPC 名字和台词写成 key（`msg.*` / `death.*` / `npc.*` / `dialogue.*`），由 `GameScene.flash` 和 `Dialogue` 用 `tr()` 翻译；地图里填的层名、位置写英文原文，中文放在 `map.<原文>` 下，由 `mapText()` 查。编辑器是开发工具，保持中文。

## 数据流

- **房间布局**：`layout` 是稀疏网格，`null` 是空位（游戏里是实心岩石）。编辑器里房间以缩略图显示，可拖拽交换 / 移动，任意空位点「+」新建，选中的房间可删除。
- **地图**：`map/world.json` 是默认地图（多层项目 `{ floors: [{ id, name, model }] }`，旧的单层格式也能读）；运行时在 Redux `editor.project` 里，编辑器改的就是它，游戏也用它。开发版自动存进编辑器的工作区（`editor` 那一份，见 [docs/desktop.md](docs/desktop.md)）。开发服务器下编辑器有「写入 src/map/world.json」按钮（Vite 插件 `climb-save-map` 提供的 `POST /__climb/save-map`），一键写回源码；打包版本用「导出 world.json」手动覆盖。
- **存档**：玩家的进度在 Redux 的 `run` 切片（结构见 `type/run.ts`），2D 和 3D 共用一份，`redux/persist.ts` 落盘（和语言、音量一起存成很小的一份 `save`：网页是 localStorage，桌面版是用户数据目录下的 `save/save.json`，Steam 自动云同步它；地图更新后进度保留、只是从那一层的出生点开始。详见 [docs/desktop.md](docs/desktop.md)），带版本号。只在检查点写：进层、换房间（`GameScene.saveCheckpoint`）、跳出 / 回到画面；记的是哪一层哪个房间、长大阶段、各机制要带走的东西（`carry`：手上的道具、帽子……按机制 id 存）、统计数字、人在哪个世界。存档版本 2；第 1 版的存档（帽子、道具是单独字段）读进来自动转换。读档 = 回到检查点：那一层按初始状态重建，人出现在那个房间（炸掉的地形不记）。标题页有存档时提示变成「继续」，左上角多一个「新游戏」；真通关后存档清空。编辑器试玩不读不写存档。层与层之间在 Phaser 里还是用 `StartGameData` 带东西（试玩也走这条路）。迷雾和引线的 `toState` 留着，将来要存它们时用。
- **参数**：`game/config.ts` 是默认值，运行时在 Redux `config` 里，将来可以做调参面板。
- **Phaser → React**：场景和 core 把展示数据 dispatch 到 `hud`；机制不直接碰 store，设置走 `PlayContext.settings`。**React → Phaser**：`protocol/` 的事件总线（事件和参数都有类型），或场景启动时传数据。
- **引擎边界**：`game/`（Phaser）和 `stage3d/`、`world3d/`（three.js）互不引入，只通过 `protocol/` 和 Redux 说话；`protocol/` 自己不依赖任何引擎。规则写在 `eslint.config.js`（`no-restricted-imports`），违反了 lint 不过。
- **3D 舞台**：游戏画面是舞台上的一块屏幕。平时舞台不画，玩家看到的就是游戏画布；有舞台特效在放时，游戏画布藏起来照常画，每帧当贴图贴到屏幕上（`game/core/ScreenFeed.ts` 实现 `protocol/screen.ts` 的 `ScreenSource`），特效放完再还回去。发 `EVT.stageFx` / `EVT.stageFxEnd` 放 / 收一个特效（id 在 `STAGE_FX`），参数在 `config.stage3d`。开发期按 T 试「画面往后倒」（`dev/stageKeys.ts`）。
- **主角跳出画面**：发 `EVT.heroPopOut`，`game/core/PopOut.ts` 等人归玩家管的时候把人藏起来、发 `EVT.heroLeft`（带 `HeroHandoff`：人在画面上的位置、大小、朝向、贴图、一格多大）；`ui/stage/StageLayer.tsx` 在舞台上把 `World3D` 带起来，人从画面上原来的位置飞出来，落地后归玩家管（方向键 / WASD 走，空格跳；手柄的左摇杆 / 十字键和 A 也一样，触屏按键也能用）。2D 游戏照常在屏幕上跑，只是没人操作、人也死不了。走回屏幕（碰到它）就回 2D：从屏幕的哪碰到的就落在画面的哪——3D 一侧发 `EVT.heroEntry` 问 2D 一侧那里能不能站，是墙或尖刺就给最近的安全空地（`game/core/popOutSpot.ts`，纯计算有测试），人飞到那、镜头回到原位，再发 `EVT.heroReturn`（带落点）。在 3D 世界里按 R：画面照样被攥成纸团、房间重置，人留在 3D 世界；这时攥屏幕的披风骷髅本人站在屏幕左边，是真的三维（`stage3d/fx/crumple/Reaper.ts`）：只有上半身，从屏幕左边的地里探出来、侧身朝着屏幕；身体是把 `skeleton.png` 上半截一个像素一个方块立起来（每一行按宽度鼓成椭圆），靠镜头这边的手伸出去抓屏幕，手臂和手是一根根骨头（`handBones.ts`，和 `grab_hand.png` 同一副骨架，手指按握拳程度一节节弯过去扣住纸团，纯计算有测试），动作和 2D 里伸进画面的那只手是同一条时间线，镜头拉远看着它，攥完再回到人身后。关卡数据在 `world3d/levels/`（单位是格，原点在屏幕底边中点），手感和镜头在 `config.world3d`。存档里人在 3D 世界时，继续游戏会先在 2D 出场再跳出去（3D 里的位置不记）。开发期按 P 跳出 / 回去。
- **节奏关卡（技术验证）**：最后一层「庆典大厅」（`levels/festival.txt`）是 Game Master 的 Boss 战：主角在左边，Game Master 和钢琴在右边，他先说开场白（用的就是平时的对话框 `Dialogue.talk`：前三句跳一下翻一句，这时候主角照常能跳；从「来吧 来吧 来吧」开始跳不过去、自己往下走：这一句一声比一声大——台词的 `grow` 字段，文案用 `|` 分截；最后一句「让我……」出来一秒后，画面正中砸下一行大字「更加尽兴吧！」——台词的 `shout` 字段），说完安静一秒，他把钢琴变出来；然后是引子（`game/mechanics/rhythm/Lure.ts`）：他弹一下琴键放一块板，一块块飞到主角前面，这时候主角是自由的——跳上哪一块，那一瞬间就被锁进节奏关卡：Game Master 的血条出现，一格一格「滴滴滴」地填满（和史莱姆王出场同一声；越往后的管填得越快、音越高，每满一管震一下，`RhythmFight.ts` 的 `FILL`），填满了曲子才开始，那块板就是 Give It Up 的起点，主角跟着曲子玩，**每一段换一种玩法**；前面一直在 2D 画面里（音符从钢琴那边过来），曲子最高潮时破屏到 3D。谱面的 `arena` 写明在哪一层打：进了那一层自动开打；开发期在别的层按 B 会先传到庆典大厅（编辑器里的地图没有这一层就从打包的默认地图里借），打的时候按 B 是中途退出；发 `EVT.rhythmStart`（带谱面 id）/ `EVT.rhythmStop` 也一样，结束时发 `EVT.rhythmEnd`。
  - **它是一个通用机制**（`game/mechanics/rhythm/index.ts`，id `rhythm`，每一层都启用）：自己听 `EVT.rhythmStart` / `rhythmStop`，场地（谱面的 `arena`）不是这一层就先传过去；进了场地这一层就摆好场子。开打以后它通过 `Mechanic.takesControl()` 接管按键和人，场景不让人走、不响应跳和 R——GameScene 里没有节奏关卡专门的代码。开场白（前几句跳一下翻一句、后面几句自己往下走）写在谱面的 `intro` 里。
  - **谁管什么**：`rhythm/` 是引擎无关的部分（谱面、判定计分、指挥），两边共用；`game/mechanics/rhythm/RhythmFight.ts` 是整场的主持，也管 2D 的段落（画在游戏画面里：压暗房间、Game Master 和钢琴、主角的替身——真的主角藏在原地不动）；轮到 3D 的段落它让主角从替身的位置跳出去，舞台上的 `world3d/rhythm/RhythmWorld.ts` 接着玩（屏幕往后倒 `screenTilt` 度，画面里的四条道接上画面外的大道），轮完、或者谱面走完，人回到画面里。
  - **对拍**：两边都听同一个指挥（`rhythm/Conductor.ts`：曲子现在第几毫秒，以音频播放位置为准），音符的位置按时间算、不按帧累加，卡顿也不跑拍。
  - **谱面**（`rhythm/charts/`）分成几段，每段写明玩法；按「步」写，一行一步、一条道一个字符，`bar()` 写一小节。`chartErrors` 检查字符、整小节、一行几个音符、躲不掉的行、每段开头留没留空（音符提前 `config.world3d.rhythm.travelBeats` 拍出发，换玩法和破屏也在这一小节里）。
  - **玩法**（`rhythm/modes.ts` 里登记谱面怎么写、在哪个世界、音符飞多快）。2D 的在 `game/mechanics/rhythm/modes/`：`giveup` Give It Up（小人跟着拍子在柱子上自己跳，上高柱 / 跨尖刺的那一拍按空格）、`dash` 喵斯快跑（重力翻转：只用空格，按一下重力翻一次，人在地面和天花板之间飘过去，方块到跟前时人在它那一排就接住）、`taiko` 太鼓（红的按 A、蓝的按 D，按哪个鼓面变哪个颜色）、`mania` 节奏大师（三条道从上面落下来，A S D，带长按，每拍有拍线）。3D 的在 `world3d/rhythm/modes/`：`osu` 点圈（像 QTE：环缩到和圈重合时按 Q W E R，带长按的圈）、`saber` 光剑（A D 换道、镜头跟着歪，方块到跟前按空格砍）、`dodge` 躲（A D 换道躲红墙，空格跳过黄杠，地面提前亮出下一排撞哪）。
  - **长按**：谱面上长按的头（玩法的 `holds` 字符）下面跟着几行 `|` 就按住几步；头和尾巴各算一次判定（按到尾巴 Perfect，提前松手 Miss）。判定在 `rhythm/score.ts` 的 `NoteTrack.holds`。
  - **2D 的衔接**：每种玩法的道具（轨道、鼓、打击框……）是一个容器，轮到它时 Game Master 从手里扔过来（划弧线、转着、由小变大落到位），轮完原地缩小淡出；同时他头顶弹出一句话（`rhythm.taunt.*`，比如太鼓是「欢乐时光！」）。
  - **Game Master 操控画面**（默认关着，晃起来头晕）：整个画面可以跟着拍子动——2D 里每拍放大一下、左右慢慢晃；到了 3D，屏幕每拍往后点一下头、左右歪。数值在 `config.world3d.rhythm.sway`，现在都是 0。
  - **Game Master 是活的**：2D 里他是一副骨架（`game/mechanics/rhythm/BossRig.ts`）：头和身子从侧面贴图 `skeleton_side.png`（脸朝左，`npm run gen-art -- skeleton_side.png` 画的占位图）上切下来，两条胳膊是现画的骨头、肘按肩和手现算。他会跟着拍子点头、说话时摇头晃脑；说完开场白双手一举、往下一按把钢琴变出来；每个音符出发的那一刻有一只手敲在对应的琴键上（没有音符的拍子也照着弹）；换玩法时甩手把道具扔过来。到了 3D 换一种放法：他的两只大骨手（`world3d/rhythm/BossHands.ts`，和攥屏幕的那只同一副骨架）从屏幕那头伸过来悬在大道上空，音符出发时管那半边的手挪到那条道上方、往下一松。
  - **主角的血**：节奏关卡里主角有 `heroHp`（10）滴血，HUD 上两滴一格、一共 5 格：满格是金色的心，剩一滴是红色的心，空了是空格。只有「撞上东西」才扣：Give It Up 里该按没按（撞在高柱上 / 踩到尖刺）、躲弹幕里被红墙撞到；别的玩法漏了音符只断连击、不扣血。挨一下之后 `hurtGraceMs` 里不再扣；扣光这一场就输。打完换回平时的心。
  - **Game Master 的话**：谱面的段落可以写 `say`（台词的 key）——上一段快结束时他在对话框里开始说，说到这一段开头空着的那一小节（太鼓之后是「很不错嘛？那就让我们更加的激情？！」）。
  - **滑条 / 砍回去**：osu 的滑条（谱面上 `A B C` 往右、`x y z` 往左）也是按住不放，圈带着人沿轨道滑到隔壁那一列；光剑砍中的方块会弹回去砸在屏幕里的 Game Master 身上（他红一下、缩一下）。
  - **谱面怎么排才打得了**：光剑要人自己换道再砍，所以 `rhythm/modes.ts` 给它写了 `reach`（一拍来得及换几条道），`chartErrors` 会查相邻两个音符隔得远不远；同一条道上可以连着来。整张谱压得很简单：基本只在整拍上，大多数小节两三下。
  - 打完曲子用 `fadeOutMs` 慢慢小下去，不是戛然而止。
  - **计分**（`rhythm/score.ts`，纯计算有测试）：每个音符判 Perfect / Good / Miss（时间窗在 `config.world3d.rhythm.windows`），连击遇 Miss 归零；躲的那段被打中算 Miss、躲过去算 Perfect。Game Master 的总血量 = 能打到他的音符数（躲弹幕那一段只是躲，不算）× `passRatio`（六成），固定分成 `bossTubes`（10）管、每管的滴数往上取整；亲手接住一个（Perfect / Good）掉一滴，躲过去的弹幕不掉他的血；HUD 上分成 10 管（血条下面是紫色发光的名字 GAME MASTER；打空一管露出下一管，旁边写还剩几管；管越多血条越大、一管一个颜色，最上面那一管是带流光的金色）；2D 里接住的音符会弹回去砸他。谱面走完时血空了算赢，在庆典大厅打赢就是通关。右上角是分数，画面上方弹判定和连击。各玩法的音符可以飞得快慢不同（`rhythm/modes.ts` 的 `speed`，光剑是 2 倍）。
  - **破屏的演出**：前半秒画面先震起来；到点整个画面闪一下白光，屏幕往后一倒（倒过头再弹回来一点），大道从屏幕底边一路铺到镜头前，人高高地飞出来；落地那一下脚下荡开一圈、镜头往下一沉。数值在 `world3d/rhythm/RhythmWorld.ts` 的 `BREAK` 和 `game/mechanics/rhythm/RhythmFight.ts` 的 `RUMBLE`。
  - **击中反馈**：每次按键打击点都亮一下（空按也亮，淡一些，让人知道键按到了）；打中了在音符那里炸开一圈、人鼓一下、当场出一声（`rhythm/hitsound.ts`，WebAudio 合成，Perfect / Good / Miss 三种音），画面上方弹判定和连击；漏了打击点红一下。2D 的零件（`burst` / `Receptor`）在 `game/mechanics/rhythm/modes/define.ts`，3D 的（`Bursts`）在 `world3d/rhythm/modes/define.ts`。画面底下一排键帽提示现在这种玩法按什么键（`ui/Hud.tsx` 的 `RHYTHM_KEYS`）。
  - **加一种玩法**：`rhythm/modes.ts` 里加一条，对应那一边的 `modes/` 里加一个文件（2D 实现 `FlatMode`，3D 实现 `RhythmMode`：`update` 判定、`draw` 画音符，3D 的还有机位和站位）并在 `modes/index.ts` 注册，谱面里就能用了。
  - 曲子：谱面的 `audio` 指向 `public/local/` 下的文件（技术验证用的曲子有版权，正式版要换掉）。文件不在时照常能玩，只是没有曲子、每拍合成一声「嗒」。
- **技术验证编辑器**（开发版顶部的第三个页签，`ui/lab/`）：做技术验证时用的小工具。打开就是**节奏关卡试玩**（`RhythmLab.tsx`）：下面是游戏画面（直接在庆典大厅里），上面一排按钮——点某一段就从那一段的开头开打，或者填第几秒点「开始」；不说开场白、不放板、不填血条，正在打就先收掉再从那开始；按钮下面是一条**实时谱面**（`ChartTimeline.tsx`）：跟着曲子走的时间线，上面是谱面里的音符（按道分行，长按画出长度），下面一行是你这次按的键（只记那一段在游戏里用的键），竖线是「现在」，点时间线上任何位置 = 从那一刻开始；「保存按键」把这次按的存成 `recordings/<谱面 id>.json`。默认「无敌」不掉血，打完不算通关（走的是 `EVT.rhythmStart` 带 `test: { fromMs, god }`，开始时刻之前的音符不要了）。右边的「谱面录制」是另一个工具：选一张谱、点「开始录」，听着曲子按键，每一下记下按在曲子的第几毫秒、哪个键（每一段只认这一段在游戏里用的键，别的键按了不记）（时间以音频播放位置为准，和游戏里的指挥是同一个钟）；「保存」写进 `recordings/<谱面 id>.json`（开发服务器的 `POST /__climb/save-recording`，另留一份带时间的备份，备份不进仓库），之后照着它重写 `rhythm/charts/` 里的谱面。
- **没去过的房间先睡着**：会自己动的东西（巡逻的怪物、移动方块）所在的房间玩家这一局还没进过，就原地等着；进过（`Rooms.isAwake`）才开始动，开始了就一直动（怪物走进没去过的房间也接着走）。引线、碎块下落、钥匙和箱子掉落这些玩家引起的后果不管房间醒没醒都照常发生。死亡 / R 重置整张图时所有房间重新睡着，只叫醒复活点所在的那间。
- **实心体**：会动的实心地形（移动方块、纸）和要站在它们上面的东西（箱子、钥匙）在 `core/solids.ts` 登记，碰撞器统一挂，机制之间不用互相打听。
- **文案 key**：`src/i18n/keys.ts` 从 en.json 推出 key 的类型，`ctx.die` / `ctx.fx.flash` 只收合法的 key。

## 机制（`game/mechanics/`）

玩法都是注册表里的**机制**，`GameScene` 只按生命周期调用它们，不认识具体玩法。每个机制一个文件夹，`index.ts` 里 `defineMechanic`，它的物件用 `机制.entity({...})` 注册在同一个文件夹里（`spawn` 直接拿到这个机制的实例）。

- **层机制**（`scope: 'floor'`）：决定这一层怎么玩，每层一个，接管玩家移动和按键、手机端按键布局。现在有 `platform`（平台跳 + 起跳爆炸，默认）和 `pacman`（吃豆人）。层设置里的「玩法」下拉就是这个列表；`floor.mode` 存机制 id，旧地图的 `'topdown'` 自动认成吃豆人。没选过的层，放了哪个层机制的物件就是哪个。
- **通用机制**（`scope: 'global'`）：哪层都能用，地图里放了它的物件就自动启用（`activeOn` 可以改规则）。`boss`、`goal`（终点）、`portal`（小城堡）、`textBlock`（文字方块）、`npc`（会说话的角色）、`carry`（携带，每层都开）、`slider`（设置滑块）、`locks`（钥匙与门）、`mover`（移动方块）。

机制能用的东西都在 `core/PlayContext.ts`（地形、玩家、怪物、对话、房间查询、死亡 / 换层、`mech('carry')` 拿别的机制）。可选的钩子在 `mechanics/define.ts` 的 `Mechanic`：`start`、`update`（每帧）、`updateAlive`（活着才跑）、`blocks`（额外挡路的格子）、`onRoomChanged`、`onClear` / `onReset`（重置；Boss 用返回值改复活点）、`onFuseBurn`、`takesControl`（这一刻按键和人归这个机制管，比如节奏关卡开打了）、`persist`（存档 / 带到下一层：返回这个机制自己的数据，存在 `carry[机制 id]` 下；进层时用 `ctx.carried(id)` 拿回来自己校验——新机制要带东西，存档格式和场景都不用改）、`vortexTargets`、`bake`（建地形前改模型，比如把门烘成砖）。层机制用 `hearts: true` 声明这一层有生命值（平台跳有，吃豆人没有）。机制还能声明 `roomFlags`，编辑器房间面板自动出现对应开关（吃豆人的「左右打通」）。

**加一个新机制**：`mechanics/<名字>/index.ts` 里 `defineMechanic({ id, name, scope, create: ctx => new X(ctx) })` + 需要的 `.entity(...)`，然后在 `mechanics/index.ts` 加一行 import（顺序 = 每帧调用顺序 = 物品栏顺序）。单元测试里 `phaser` 被换成替身（`tests/support/phaser-stub.ts`），所以注册表可以直接在 Node 里测。

**机制要在地图里存自己的东西**（比如移动方块的标记、钥匙与门）：
1. 在它的文件夹里写 `layer.ts`，用 `defineGridLayer({ id, table })` 登记一个格子图层（每个房间 roomH 行、每行 roomW 个字符，`'.'` 是空；`accepts` 可以拒绝不合法的字符）。不是格子的数据（比如文字方块是一串对象）用 `defineRoomData`。然后在 `game/world/allLayers.ts` 加一行。登记了之后，删房间、清空房间、改房间尺寸都会自动带上它，`layerCell` / `setLayerCell` / `layerRows` 可以读写、拼整张图，`WorldModel` 和编辑器的 reducer（通用的 `paintLayer` / `paintLayerRect`）都不用改。
2. 要在编辑器里画它：在文件夹里写 `editorTool.ts`，用 `defineEditorTool` 登记。要写的有：
   - 物品栏那一组按钮（图标、说明，可选「添加」按钮、删组的确认、开关）
   - `paint`：点一格派发什么动作，纯函数，能单测；返回 `{ status }` 就是不让画，状态栏提示原因
   - `stroke`：一格格画、拖矩形，还是只认点一下
   - `create`：编辑器画布上怎么叠加画；`prepareGrid` 可以在画砖块之前改网格，比如门烘进砖块
   
   然后在 `game/editor/allTools.ts` 加一行。`EditorScene` 和物品栏只遍历登记表。现成的例子是 `mechanics/mover/`、`mechanics/locks/`、`mechanics/textBlock/`、`game/fuse/`、`game/fog/`。
3. 文字关卡（`scripts/levelFormat.mjs`）是纯 Node 脚本，引用不了注册表，里面手抄了砖块 / 物件字符表；`tests/scripts/levelChars.test.ts` 会拿注册表核对，忘了改会报出来。

## 帽子与箱子

**帽子**（物件 `h`，`mechanics/hat/`）：黑色高脚帽，戴在头上（单独的位置，不占手，可以同时拿蜡烛 / 钥匙）。碰到就戴上（头顶要有空间），戴上后碰撞框往上加高 `hatHeight` 格：主角 1 格 + 帽子 1 格 = 2 格高。↓ / S 摘下放在脚边。戴着帽子钻 1 格高的隧道，帽子会被撞掉在隧道口，人变回 1 格继续走；刚摘下 / 撞掉的帽子要人走开之后才能再戴。换层、死亡都不掉；只在平台层生效。

**箱子**（物件 `b` 小箱子 1x1、`D` 大箱子 2x2，`mechanics/pushBlock/`）：贴着往前走就推着走（速度 `pushSpeed`，比走路慢），规则是**身高 ≥ 箱子高**才推得动：1 格高的主角只能推小箱子，戴帽子（2 格高）两种都能推。前面被砖或别的箱子挡住就推不动（不能连推）。有重力，推出边缘会掉下去；停下来自己对齐格子；爆炸炸不动；人撞不动它，可以站在上面；怪物也会被它挡住。人推着箱子顶到史莱姆，会把史莱姆一起往前推（史莱姆站在地上、前面没有墙 / 箱子 / 别的怪物才推得动，否则箱子停下），推到悬崖外它就掉下去；史莱姆自己推的箱子碰到别的史莱姆还是停下。掉得够快（≥ `crushMinSpeed`）砸到人头上会砸死人（怪物也会被砸死）；慢慢落下来不算；只擦到头顶一个角也不算（要盖住对方头顶三分之一以上的宽度，`CRUSH_MIN_COVER`），箱子会停在人肩膀上，人走开它再掉下来。箱子占着的格子算「地面」：掉下来的碎块会落在箱子上变成砖，并且算被箱子撑着；把箱子推走，上面的砖就会掉下来（站在下面会被砸）。机制用 `occupies(cx, cy)` 钩子告诉地形哪些格子被占着。死亡 / R 回到原位。大箱子在编辑器里放的那一格是它的左下角。**木板**（砖块 `_`）挡得住人和怪物、挡不住箱子：人从上面走过去（从下面能跳穿上来），箱子会从木板上漏下去。

**压板**（物件 `q` 1x1、`Q` 1x2，也在 `mechanics/pushBlock/`）：放在地上，占一个空气格，人和方块都能穿过。被压满的时候点燃紧挨着它的引线头（压板这一格和上下左右四格；这些引线头被压板锁住，爆炸点不着，只能靠压板），引线烧过接在压板上的那一头之后压板就用掉了、消失（死亡 / R 恢复）。算"压满"的有：落了地的箱子盖住压板每一格（1x2 要大箱子）；**移动方块**停在或滑过压板那一格（1x2 要两格都压着）；`config.platePressedByRubble` 打开时，掉下来落在上面的碎石等任何实心地形也算（默认关）。人踩没用。别的机制想当"重物"压压板，实现 `Mechanic.weighs(cx, cy)` 就行（移动方块就是这么接的），判断在 `pushBlock/plates.ts`。

## 塔：多层

游戏从第一个层标签开始。走进「小城堡」物件（`T`，城门在贴图底部正中）进下一层（层顺序 = 标签顺序）。进门有一段旋涡：镜头转着拉近城门，人、怪、骷髅和一把碎屑沿螺旋线缩进门里，然后淡出换层。编辑器画布上方是层标签，「添加一层」可以给每层单独的房间尺寸（比如标题层做成 40×20）。「层设置」弹窗（或双击层标签）改名字、玩法、房间尺寸；房间尺寸是这一层所有房间一起改，左上角不动，变大补空气，变小从右边和下边裁掉。弹窗里还有一栏「位置」，填了就在游戏左上角显示「当前位置: …」（深色底白字，不受画面影响；每层各自一句）；「删除本层」删掉当前层。弹窗里还有「背景音乐」：从音频清单里标了 `music` 的曲目里选（`asset/index.ts` 的 `AUDIO`，加新曲子就是加一行），或者选「无」这一层就不放音乐（存成 `floor.music = "none"`，不写就是默认的 `bgm`）。Boss 战临时换成 Boss 音乐，打完回到这一层自己的音乐。背景曲很大，启动时不加载：第一次要放时才下载（加载条只等音效），有 Boss 的层一进来就先把 Boss 曲下着。

**文字方块**（物品栏「文字」）：左键在画布上放一串字，字母由 3×5 像素字体拼成可炸的砖（默认「字块」`=`，可换成任何可炸砖）。侧栏改内容 / 砖种 / 目标层。游戏里这串字的砖全被炸掉，就淡出跳到目标层，可以拿来做标题层的「开始 / 设置」按钮。字体在 `game/world/font.ts`，支持 A–Z、0–9、`- ! ? .`、空格、换行。

## 出口与长大

走到「出口」（`G`，上面画一座小楼）：有下一层就是**假通关**：礼花 + 「通关」弹窗（跳跃 / 摧毁数），按钮是「进入下一关」，点了跳到下一层；右上角 X（或跳一下）关掉继续玩（走远一点门才会再触发）。最后一层的出口才是**真通关**：同一个弹窗，按钮是「再来一次」（从这一局的起点重开；正式游戏清掉存档，试玩回到试玩起点），X 只是收起弹窗。最后一层没有下一层时，小城堡的城门也是真结束。

**长大**（`core/Growth.ts`，现在没有东西触发，留着以后做成药水之类的道具）：身体分三阶，1 格、1.5 格、2 格（`sprite/Player.ts` 的 `STAGE_EXTRA` / `MAX_STAGE`）。以前假通关点「进入下一关」触发长大，过程是：画面淡出，整张地图复原（同死亡重置），人回到本层出生点，淡入后站着不动，身体慢慢长高半格（`config.growMs`；贴图和碰撞框一起变高，脚底不动；长到整阶换成那一阶的贴图 `player_mid` / `player_tall`，中间用当前贴图拉高），长完解冻再玩一次。长大是永久的，换层和存档都带着（`stage`）：2 格高能推 2x2 的箱子，超过 1 格就钻不过 1 格高的缝。

## 吃豆人层（俯视）

层设置的「玩法」选「吃豆人」（放了吃豆人物件的层不选也自动是），这一层没有重力，沿格子中线四方向走（想转的方向记住，到路口就转；前面是墙停在格子中央），没有跳跃和起跳爆炸。W / ↑ 是往上走；动作键只有空格（手机端一个淡白色圆键）。物品栏「吃豆人」分区：豆子（10 分）、大力丸（50 分）、鬼巢、葡萄点、隧道格；房间开关「左右打通（隧道）」让人从左边出去右边进来。右上角显示分数。死亡沿用 U DEAD，回本房间重置点；剧情开始前死亡，豆子全部复原（分数保留）。清空的判定只看小豆子，四个角的大力丸不算。

**鬼**（`game/mechanics/pacman/Ghosts.ts`）：放一个「鬼巢」在门口那一格，门下面留三格空气当巢。四只鬼：红的在门口直接出发，粉、青、橙分别 2 / 5 / 8 秒后出巢。目标各不同：红直追；粉堵你前方四格；青拿红鬼和你前方两格连线的两倍点夹击；橙离你超过 8 格才追、近了回自己角落。全体按"散开 7 秒、追 20 秒、散开 7、追 20、散开 5、追 20、散开 5、永久追"切换，切换瞬间掉头。大力丸：全体变蓝掉头减速可吃（6 秒起，每吃一颗大力丸短 0.8 秒，最短 1.5 秒；最后 1.5 秒闪白），吃鬼 200 / 400 / 800 / 1600 连击，被吃的变成眼睛飘回巢，1 秒后正常出来。鬼巢的门和巢内对人、对巡逻中的鬼都是墙。隧道格里鬼减速。人被鬼碰到 → 死亡。死亡 / R 重置：鬼回巢重新按节拍出，豆子复原（清空之后的追击阶段不复原）。**葡萄**：吃到第 70、170 颗豆子时在某个葡萄点出现 9 秒，吃到 300 分。

**画面**：鬼身体白底按只染色（`ghost.png` / `ghost2.png` 两帧裙边交替），眼珠跟着前进方向偏，蓝色惊吓态换锯齿脸并在最后闪白，眼睛态只剩眼睛，被炸死留一团散开的影子。手机端俯视层是 ▲▼◀▶ 十字键 + 一个无字的淡白圆键（炸弹）。

**清空之后**（`game/mechanics/pacman/PacScript.ts`，按时间戳推进，死亡重置不打断）：豆子吃光不结束，鬼提速 1.5 倍、永久追击（散开节拍作废，蓝色立刻结束）。6 秒后自动翻页的画外音（`pacman/dialogues.ts` 的 `taunt`，每句 `autoMs`），再 1 秒解锁**炸弹**（`pacman/Bombs.ts`）：只有空格（手机端动作键）能放，一开始同时一颗，实体，人走开之后挡路（鬼也绕着走），1.5 秒后炸十字（四个方向各 2 格，岩石挡住，可炸砖炸掉并挡住后面）。炸到鬼鬼就死且不复活（500 分），炸到自己也死——鬼全灭之后炸弹就不伤自己了；死后回到的还是追击阶段（鬼仍然快、炸弹仍然有），不是重头来。**大力丸在 2 阶段是强化道具**：进 2 阶段的那一刻、以及每次死亡复活，地图上的大力丸全部刷新；2 阶段吃一颗，鬼不变蓝，改成移速 + `pacBoostSpeed`、能同时多放一颗炸弹（从 `pacBaseBombs` 起，最多 `pacMaxBombs` = 5），死了加成清零、要重新吃。数值都在 `game/config.ts`。鬼全灭 2 秒后 Game Master 的对话（`king`），说完淡入出现在你面前两格，后续剧情待写。

## 携带（共用机制）

手上只有一个位置。蜡烛、钥匙都是"拿在手上"的东西：碰到就捡，手里已经有东西时两者交换，旧的留在原地（人走开之后才能再捡）。钥匙开门后用掉，手就空了。换层只带道具（蜡烛），钥匙留在本层。

## 钥匙与门

物品栏「钥匙与门」里点「添加一组」，每组一个颜色（蓝、绿、黄、红、紫、橙、粉、白、青，最多 9 组），同时出现同色的「钥匙」和「门」两支画笔。门可以画在空气上，也可以盖在别的砖上（比如尖刺）：编辑器里门格右下角画一个被盖住的砖的小图标，游戏里一开始看到的是门，开门后露出下面的砖（`LockCell.under`）；右键擦。钥匙放地上。地上的钥匙画成两倍大（占一整格，拿在手上是 1.5 倍，`Carry.ts` 的 `KEY_SCALE`），背后一圈同色的光一胀一缩、时不时闪一两颗亮点，比较显眼；捡到时叮一声（`asset/key_pickup.mp3`，`bash scripts/gen-sfx.sh` 用 ffmpeg 合成的，可以直接换成手工音效）。地上的钥匙有重力、有碰撞体积（`mechanics/carry/LooseKeys.ts`，参数在同目录 `keyFall.ts`）：悬空、脚下的砖被炸掉就往下掉，掉得快的落地弹一两下、压扁一下、溅几颗同色火花，在空中微微歪；和砖块（木板上站得住）、纸碎块、箱子、移动方块碰撞；怪物走过来会用自己的速度推着它走，推到墙上怪物掉头，推出平台边钥匙就掉下去；玩家不和它碰撞，碰到就捡。被落下来的碎块埋住会挪到上面第一格空处。按 R 时出生（或被放下）在这个房间、或者现在就在这个房间的钥匙回到原位，死亡重置整张图时全部回去；蜡烛还是固定在原地。**开门的是钥匙本身**：钥匙碰到同色的门，这扇门就打开，钥匙用掉。碰到钥匙会把它拿在手上（占用唯一的携带位，见上一节），拿在手上时人碰到门就算（走过去贴上、踩在门上、头顶着门都行）；地上的钥匙掉到门上、被怪物推到门上也一样会开（`Locks.updateAlive` 对每一把钥匙用同一段判断，钥匙列表来自 `Carry.keysInPlay`）。门开了之后**连锁**：沿上下左右相邻的同色门一格格传下去，连在一起的这一片门依次消失（每格间隔 `config.lockChainDelayMs`，默认 70 毫秒；设成 0 就整片同时开）。钥匙直接放在同色的门上，一开局门就开了。斜着挨着的不算相连；不同色的门会挡住连锁；同色但不相连的另一片门还锁着，要另一把同色钥匙（`mechanics/locks/cluster.ts`）。门的形状就是开门的范围：想一把钥匙开一整面墙，就把门画成连在一起的一片。**重置房间**（R、Boss 战打到一半死了）：这个房间里开过的门关回来，开这些门用掉的钥匙回到原位（不管钥匙是从哪个房间带来的，不然门关了钥匙没了就卡死）；别的房间的门不动，用在别的房间的门上的钥匙也不回来（不然能刷出两把）。重置整张地图时所有门关回来、所有钥匙回原位。死了不重置（默认）时门和钥匙都保持原样。数据在 `model.locks`（`groups` / `doors` / `keys`），门在游戏里烘成 `%` 砖再按组染色。

## 移动方块

物品栏「移动方块」有两支画笔：**左右移动**（一开始往右走）和**上下移动**（一开始往上走），种类在 `mechanics/mover/kinds.ts` 的 `MOVER_KINDS`（加一种新的移动就是加一行）。标记画在方块上（`model.movers`，叠在砖块层上，右键擦掉），编辑器里显示成蓝色 ⟷ / 粉色 ↕ 箭头。

- **能放在哪**：实心、自己不会往下掉的砖（岩石、碎岩、字块、木板）。沙土、脆岩、纸这些带重力的不行：编辑器里画不上去，后来被换成这类砖的标记显示红叉，游戏里忽略。
- **一组一起走**：上下左右相连的同一种标记是一组，连同底下的方块一起沿一根轴来回走（`config.moverSpeed`，默认 64 像素/秒 = 两格/秒）。
- **撞到就掉头**：每走一格之前检查整组所有格子在前进方向上的下一格，任何一格被挡（地形、箱子、炸弹、别的移动方块、正要进同一格的另一组、没站在上面的人或怪物）就停一下（`config.moverPauseMs`）掉头。往上运人时人头顶一格有墙也算挡住；走到一半有人跳上来、或者走进路线里、再走就会被夹进墙的话，当场退回去。
- **站在上面会被带着走**：人、怪物、箱子都能站在上面（左右移动时箱子被带着走可能和它自己对齐格子的逻辑打架，尽量别这么摆）。
- **方块没了就不走了**：那一格变成空气（被炸没、被引线烧没），它就退出这一组，剩下的照样一起走。岩石被引线烧成碎岩还算在；碎岩再没了才真没了。
- **地形照常算**：方块一直在地形网格里，每走满一格才在网格里挪一格（走到一半时网格里还是原来那格），爆炸、引线、支撑、迷雾都照常作用在它们身上。挪开之后，原来靠它撑着的沙土会掉，挂在上面的尖刺会碎。
- **能压压板**：停在或滑过压板那一格时压板算被压下（见上面的「压板」），可以用来做定时触发的机关。
- **重置**：按 R、死亡（设置成死了要重置时）时，所有移动方块都回到一开始的位置（和引线一样，全图一起），被炸掉的格子按地形重置的规则恢复。

实现在 `mechanics/mover/`：`kinds.ts` 是纯函数（能不能放、怎么分组、撞没撞），`Movers.ts` 是运行时。瓦片层不画这些格子（机制钩子 `drawsCell`），由机制自己画、自己做碰撞（每行连着的格子一个 Arcade 物理体，直接改位置 `directControl` + `friction.x = 1`，站在上面的就会被带着走）；`Terrain.moveCells` 负责在网格里整组平移。

## 设置房间的机关

「音量滑块」物件（`V`）：放在地上，喇叭图标右边伸出一条 8 格长的轨道，上面一个滑钮。走过去把它推到哪儿，音乐就多大（`config.musicVolume`，即时生效、记在本地）；喇叭旁边的声波弧线跟着变，推到最左是静音的红叉。滑块绑定的是 `GameConfig` 里的数字字段，以后要加别的设置就是再放一个绑不同字段的物件。

## 会说话的角色

「骷髅」物件（`N`）是挡在路上的小角色。走到它跟前一格半内强制进入对话（左右移动锁住，只能跳），每跳一次（也就是每炸一次）说下一句；最后一句说完再跳，它带着笑声（`bossLaugh`）淡出消失，路就通了。消失是这一层内永久的，死亡重置不会把它带回来。台词在 `game/mechanics/npc/dialogues.ts`，新角色 = 一段台词 + 一个 `npc.entity`（`spawn: (n, at) => n.addNpc(…)`）。放它的时候脚下用岩石，不然玩家跳的那几下会把它脚下炸空。

## Boss 房间

物品栏里的「Boss 史莱姆王」物件（`K`）放进哪个房间，那个房间就是 Boss 战。玩家进来先没事；往里走到离门口一格半以上（房里涂了「Boss 触发点」`k` 的话，要先碰到其中任何一格；触发点按住拖动可以连着涂一片，游戏里看不见，物品栏里和 Boss 一左一右挨着；没涂就是走离门口就算），房间四条边上的开口（左右、上下都算）全部封上「Boss 封门」砖（`boss/seal.ts`：长得像岩石，炸不动、引线也烧不开），复活点就定在这个位置，随后放一段出场过场：WARNING 警报（`asset/warning.mp3` 用 1.5 倍速正好放两遍，显示多久跟着音频长度走）→ 安静 1 秒 → 史莱姆王从放物件的那一列尽量高的地方落下 → 落地后顶部 6 格血条（`bossHp`）一格格涨满、每格「滴」一声 → 像素字体亮出「SLIME KING」、Boss 曲响起 → 才开始动（时长是 `BossFight.ts` 顶部的 `WARNING_PLAYS` / `WARNING_RATE` / `PAUSE_MS` / `FILL_STEP_MS` / `TITLE_MS`；「滴」和亮名字那一下是 `boss/bossSound.ts` 现场合成的）。过场中它不动、打不疼、碰到也不死。碰到即死的范围贴着贴图的圆顶拼成几块，比画出来的身体往里收 4~8 像素（`Boss.lethalRects`），宁可擦边活下来。它的循环是：游走两三跳（每跳 3 格高，离玩家太近往外跳、太远才靠近）→ 蓄力 0.7 秒（压扁变暗）→ 用力一跃（4~5 格高，按滞空时间算横向速度）扑向玩家当时的位置、落地重震 → 喘气 1.6 秒并吐 2 只小史莱姆（绿色、0.65 倍大小，碰撞框一起缩；两次吐怪至少隔 `bossSpitMs`；只数这个 Boss 房里它自己吐的、还活着的，上限 `bossMaxMinions` = 6，地图上的巡逻怪不算；Boss 倒下的一瞬间小史莱姆全部一起死）。喘气那段是砸它的窗口。碰到即死。玩家老贴着它：每次它要跳 / 要扑的时候玩家都在 3.5 格以内，连着 2~3 次它就被吓到 —— 一哆嗦、头上冒「!」，然后往房间里离玩家最远的那头大跳过去（5 格高，空中一直保持横向速度，撞上小台子会蹭过去），起跳时脚下铺一滩黏液、再朝玩家甩两团，落地各摊成 3 格宽的一滩，10 秒后淡掉。玩家站在黏液上像溜冰：按方向键只能慢慢加速、慢慢转身，松手要滑好几格，撞墙才停（`BossFight` 的 `ICE_ACCEL / ICE_FRICTION`，在玩家正常移动之后改速度）。画面上它是一个会动的果冻：部件在 `boss/bossArt.ts` 画，`boss/BossView.ts` 按它在干什么动（起跳蹲、落地压扁回弹、眼睛盯人眨眼、表情跟着蓄力 / 喘气 / 挨打 / 受惊变，王冠晃）；物理体不变形，致命范围不受影响。**只有落石和引线能伤它**：快速下落的碎块砸中扣最多 4 格并被它吞掉，引线烧过的格子碰到它扣 2 格；受击后 0.8 秒无敌（闪烁），所以一次落石、一次引线各只算一下；起跳爆炸不伤它。血条清空后开门，同时 Boss 爆开射出一圈**穿墙火花**（`bossBurstCount / Speed / Ttl`）：不伤任何人，碰到引线端点就点燃。把引线埋在 Boss 房地板下、连到别处的门，打赢 Boss 就自动开路。Boss 房里还可以画「王之炸药」砖块（`E`，`boss/charge.ts`）：平时是一块人炸不动、引线烧不坏的墙；史莱姆王一死，火花圈扩到哪块它就跟着炸（按离 Boss 的距离排队）：周围 3x3 的实心方块全没（岩石也是，锁着的门和封门除外），范围里每一格的引线（不只端点、任何颜色）都从那里点着，周围的脆岩 / 纸被震下来，挨着的另一块王之炸药隔 0.14 秒接着炸。爆炸不伤人；死亡 / R 跟着地形复原。打赢之前死掉或按 R，都回到关门的位置重来，门重新关、Boss 重新出场。打赢之后这个房间就不再出 Boss（死了也不会回来，见「死了之后重置什么」）；在这个房间里按 R（房间复原）、或者设置成死了重置整张地图时，Boss 回来，重新打。参数在 `config.bossHp / bossHopMs / bossSpitMs / bossMaxMinions / bossMinionScale / bossMinionHue`（颜色是把怪物贴图的色相整体转 `bossMinionHue` 度，见 `boss/minionTexture.ts`）。

## 地图迷雾

`game/fog/Fog.ts`。两样东西，分开用：

- **迷雾区**（藏东西）：编辑器里画 1-4 号区，任何房间都能画（不影响地形）。没揭开前**伪装成墙**：区里的空格画成附近最多的那种实心砖（假墙，一般是岩石），画在最上层，里面的物件、怪物一起挡住；光也像真墙一样照在表面、透不进去。看起来就是一整块实心的地形，看不出藏了东西。玩家踏进区内任一格（复活时被骷髅手拎着路过不算，落了地才算）、或者区里有砖被炸掉 / 烧掉，整区永久揭开，假墙在 0.4 秒里淡掉（`ZONE_REVEAL_MS`）。用来藏墙里 / 地里的秘密通道和密室；画在半空的空地上会凭空出现一块石头，别那样用。房间里没画迷雾区的地方正常显示。
- **全屋暗**（整个房间黑）：房间面板里勾「全屋暗」（`roomFlags[房间].fog: true`，默认不开）。整个房间只看得见光照到的地方，三种状态：没见过（很暗，隐约看得出轮廓；浓度 `config.fogUnseenAlpha`，默认 0.85，1 = 全黑；爆炸预览不显示）、见过但不在视野（半透明，`config.fogMemoryAlpha`）、视野里（清晰）。迷雾区的假墙和真墙一样被照亮 / 变暗。
  - **光照扩散**：以玩家为圆心的圆，亮度按直线距离衰减；光沿空气传播，实心格被照亮但挡住后面。没有光源时只看得见身边（`config.fogRadius`，1.5 格）；地上放一支「蜡烛」物件（`C`），它在地上自己就亮着（迷雾里远远能看见那一圈光），碰到就捡起来拿在右手，照明半径变成 8 格（道具的 `light`，在 `Items` 注册表里）。捡到的道具换层、死亡都不掉。炸开一堵墙，光会立刻透进去。
- 两样都没有的层不建迷雾层。探索记忆和揭开的迷雾区不随死亡 / R 重置消失。
- 画法：先画迷雾区的假墙砖，再把全屋暗的光照（每格一个浓度的小图 `FogLayer`，平滑放大，光圈是圆润的渐变）盖上去，都画进一张房间大小的 RenderTexture；只在玩家换格子、地形变化、假墙淡出时重画。每格有多清楚看 `FogOfWar.clarity`，假墙看 `FogOfWar.fakeWall`。

## 画面效果

每样都能在 `config.sceneFx` 里单独关掉（`shadow / depth / vignette / dust / lights / shafts`）。

- **背景**（`game/background/`，清单在 `asset/backgrounds.ts`）：每层一个默认背景（层设置里的「背景」，地图里的 `Floor.background`），房间可以单独换（房间面板的「背景」，`WorldModel.roomBackgrounds`）；都没写就是程序画的渐变天空 + 星星。一个背景可以叠几层图（从远到近），每层有视差：人在房间里走，远的层挪得少、近的挪得多（`parallax` = 人走过整个房间时那层挪多少像素）。背景图不在启动清单里，**进到用它的那一层才加载**（加载完之前先显示星空），换层时把用不到的背景图放掉；每个房间各放一套、裁到房间大小，平移时相邻两个房间各显示各的，只有镜头看得到的房间才显示。加背景：图放进 `src/asset/backgrounds/`，清单里加一项（占位图：`npm run gen-art -- backgrounds`，现在有洞穴、黄昏两套）。文字关卡里写 `background <id>`、`roombg <房间> <id>`。编辑器里能直接看到当前房间的背景。
- **层次**：前后顺序（Phaser 的 depth）集中在 `game/depth.ts`，背景在最下面（星空 −10、背景图 −9.95 起、星星 −9），光柱、微尘在背景之上、地形之下，迷雾最上面。新加的东西先在那张表里找位置。

- **暖光**（`core/sceneFx.ts` 的 `LIGHTS`）：地上的蜡烛、拿在手里的蜡烛（跟着手走）、引线头周围一小圈淡淡的暖光，叠加混合，贴着它的墙和背景稍微变亮、带点暖色，轻轻摇曳。蜡烛半径 1.8 格，引线头 1.1 格。机制里要放光：`ctx.fx.light(x, y, 'candle' | 'ember')`，返回的图片自己挪、自己销毁。
- **光束**（`core/sceneFx.ts` 的 `SHAFTS`）：每个亮着的房间 2～3 道从房顶往右下斜照的淡光，画在地形后面，只在空旷处看得见、被墙挡住，像从天花板缝里漏下来的；慢慢呼吸、轻轻摆。位置按房间编号定死，每次进来都一样。全屋暗的房间没有。
- **墙的投影**（`Terrain.enableShadow`）：同样的砖再画一层，往右下挪 4、5 像素、染黑、35% 透明，垫在地形后面 —— 墙在背景上落一道硬边的影子，看着浮在背景前面。砖块变化时跟着改。移动方块、掉落的碎块没有投影。
- **体积感**（`Terrain.enableShading`、`terrain/shading.ts`）：实心砖越往里越暗（按离最近的空气几格：表面不变，第 2、3、4 层依次加深，`SHADE_BY_DEPTH`），一格一个点的小图平滑放大盖在地形上；墙越厚越明显，一两格厚的墙几乎看不出来。
- **暗角**：镜头滤镜，四角暗两成多、四边中点一成不到（只有 WebGL 有）。
- **微尘**：当前房间里同时飘三十来粒很小的光点，慢慢往上、左右晃，出生和消失时渐隐。

## 墙的拼贴（现在没用上）

一套备用的画法：砖块只有朝外的那一圈表面有纹理，被同类墙团团围住的内部是黑的（和迷雾同色）。现在没有砖这样画（试过岩石，占位图不好看，先撤了），代码留着，手画好模板就能用。

- **模板**：一张 5×3 格的图（一格 32 像素），按这个位置画：

  | | 第 0 列 | 第 1 列 | 第 2 列 | 第 3 列 | 第 4 列 |
  | --- | --- | --- | --- | --- | --- |
  | 第 0 行 | 左上角 | 上边 | 右上角 | 左上折角 | 右上折角 |
  | 第 1 行 | 左边 | 中间（黑色内部） | 右边 | 左下折角 | 右下折角 |
  | 第 2 行 | 左下角 | 下边 | 右下角 | 空着 | 空着 |

  「折角」是凹进去的内角：比如左上折角 = 上面、左边都是墙，只有左上斜角是空的。表面那一圈最多画半格（16 像素）厚。
- **启用**：模板放进 `asset/`，在 `asset/index.ts` 里 import、加到 `WALL_TEXTURES` 和 `IMAGES`，砖块定义里写 `wall: WALL_TEXTURES.xxx`。编辑器里照样整块画。
- **拼法**（`game/terrain/walls.ts`）：每块砖分成四个角，各看挨着的竖边、横边、斜角邻居是不是墙，从模板对应那一格取同一个角拼起来；一格厚的平台、孤零零一块这些薄墙也能拼出来。拼法固定，同样的地形每次一样。启动时拼成一张 `walls` 图（47 种组合），地图 tilemap、掉落碎块、移动方块都从里面取。只有写了 `wall` 的砖之间算连着，地图外面也算；被移动方块接管的格子不算。

## 规则与砖块

基础砖块在 `game/registry/tiles.ts` 注册（属于某个机制的砖块，比如门 `%`，在那个机制的文件夹里注册），用特征组合声明：

```ts
defineTile({ id: 'B', name: '脆岩', color: 0xc9b27c, frame: TILE_FRAMES.brittle },
  Traits.Solid, Traits.Destructible(1), Traits.Chain);
```

| 能力 | 含义 |
| --- | --- |
| `Solid` | 实心，挡住玩家、怪物、碎块 |
| `Anchor` | 锚点：自己永不掉落，相连的实心格子都被它撑住 |
| `Destructible(n)` | 可被爆炸摧毁；`n` 是额外感应半径（格） |
| `Chain` | 被波及后沿同类格子连锁崩塌 |
| `Loose(n)` | 周围有爆炸就整块松脱掉落（范围外再加 n 格感应），相连同类一起掉 |
| `Hazard('提示')` | 碰到即死 |
| `Delay(ms)` | 连锁传导时每跳延迟 ms 毫秒才摧毁，能看到火苗跑过去 |
| `EndsOnly` | 只有链条两端能被爆炸点燃，中间段免疫 |
| `Mounted` | 挂在下面那一格上：下面那格被炸掉、被引线烧掉、或者掉下去，它就一起碎掉（尖刺用的就是这个） |
| `SideMount(…)` | 配合 `Mounted`：下面空了改挂在旁边。左边是墙挂左边、右边是墙挂右边、两边都是墙挂两边（木板不算墙），三边都空才碎；每种挂法有自己的帧和致命区域（尖刺：挂一边的刺伸出 14 像素，两边都挂时缩小一半、每边上下各两排）。判断在 `terrain/support.ts` 的 `mountSide`，选帧在 `frames.ts`，致命区域是 `Terrain.hazardBoxes` |
| `OneWay` | 单向平台：人和怪物只能从上面落上去站着，从下面、侧面都能穿过（木板） |
| `BoxPassThrough` | 箱子不跟它碰撞：箱子站不住会漏下去，也能推着穿过（木板） |
| `CracksTo(id)` | 被引线烧到时不消失，变成 `id` 这种砖（岩石 `R` → 碎岩 `r`） |
| `Fireproof` | 引线烧不动它（锁着的门、Boss 封门、脆岩）；引线本身照样从这一格烧过去。会松脱的（脆岩）照样被火震松掉下来，只是不会被烧没 |
| `Hidden` | 不在编辑器物品栏显示 |

### 角色技能

起跳时发生什么也是注册表（`game/registry/skills.ts`）。技能拿到一个 `SkillContext`（查地形、摧毁格子、放特效），自己决定炸哪里、预览画什么：

```ts
defineSkill({
  id: 'drill', name: '定向钻孔',
  onJump(ctx) { const removed = ctx.destroy(ctx.previewCells(cells)); ctx.fx(ctx.jump.cell, removed, 1); },
  preview(ctx, jump) { return { outline: cells, removed: ctx.previewCells(cells) }; },
});
```

当前有 `blast`（默认，起跳点圆形爆炸）和 `drill`（示例，1 格宽 3 格深的定向钻孔）。用哪个由 `config.skill` 决定，游戏页有下拉可以切换。

### 引线（`game/fuse/Fuse.ts`）

引线**不是砖块**，是叠在地形之上的一层（`model.fuse[房间]`），不占格子、不挡人，可以穿过空气和任何砖块。只有两端（同色邻居 ≤ 1）能被爆炸点燃（`config.fuseIgniteRadius`），点燃后从那头沿引线一格格烧过去（`config.fuseDelayMs`），烧到哪格就烧那格的地形（`Terrain.burnCells`）：**岩石烧一次裂成碎岩 `r`**，碎岩再被引线烧一次、或者被人炸，才真的没了（**紫色引线**更猛，岩石一次就烧没，不留碎岩：`channels.ts` 里的 `shatter`；它的引线头在游戏里也更大，带呼吸的紫色光晕和往上冒的火星：`node`）；其它实心砖烧一次就没（脆岩除外：防火，火穿过它只会把它震松、整块掉下来）（岩石和碎岩都是锚点，没了之后周围失去支撑的沙土 / 脆岩会跟着掉）；经过空气只是过一下。已经在烧的那段再点一次不会重复烧：火从两头烧过来在中间碰头，每格只烧一次。

**颜色**（`game/fuse/channels.ts`）：编辑器里有橙、蓝、绿、紫四种引线，游戏里橙、蓝、绿长得一样，紫色的引线头更大、带特效。每种颜色是一张独立的网：只和同色相连、只点同色的端点、只沿同色烧。不同颜色可以画在同一格（交叉），交叉点互不连通、互不引爆；一种颜色烧过交叉点只烧掉自己，另一种颜色还在，之后照样能烧（比如先用橙线把岩石烧裂，再用蓝线把碎岩烧掉）。地图里每格是颜色位掩码：`'.'` = 无，`'W'` = 只有橙色（老地图不用改），`'2'`-`'f'` = 十六进制；存档里每格一位十六进制。压板锁住的端点、Boss 火花点燃的端点也都按颜色算。编辑器右键只擦当前颜色。

游戏里只画端点（黄色节点），中间段完全不可见；编辑器里整条线自动拼贴显示。R 重置房间会恢复这个房间里的引线。引线可以**跨房间**：两个房间交界处相邻的引线格会拼成一条，火照样烧过去；编辑器里边缘格会显示成连向隔壁，缩略图上也画出引线方便对齐。注意 R 只恢复当前房间那一段，已经烧到隔壁的部分不会回来；按 R 时整张图正在烧的引线全部停下（没烧到的那段之后还能再点）。

引线在编辑器里的贴图是**自动拼贴**：按上/右/下/左有没有引线取 16 帧之一（`frame + 掩码`，上=1 右=2 下=4 左=8）。砖块系统也支持同样的机制：任何砖块加上 `autotile: true` 并在图集里放 16 帧即可；`gameFrame` 可以让砖块在游戏里和编辑器里长得不一样。

新砖块要有图集帧：在 `scripts/gen-art.mjs` 里画一帧（或换成手绘 PNG），在 `asset/index.ts` 的 `TILE_FRAMES` 加序号，然后注册。

## 生命值

`game/core/Health.ts`。玩家有 3 颗心（`config.playerHearts`），显示在左上角（像素心 `asset/heart_full.png` / `heart_empty.png`，`npm run gen-art -- heart_full.png heart_empty.png` 生成；地点名挪到心下面）。碰到**尖刺、怪物、Boss** 扣一颗心（机制里用 `ctx.hurt(原因, 伤害从哪来)`）：人整个变红一下（`hurtFlashMs`），往伤害来源的反方向弹开（`knockbackX / knockbackY`，弹开的 `knockbackMs` 里不听方向键；来源在脚下就往朝向的反方向、主要往上弹），左上角那颗心抖一下变空，人一闪一闪 `hurtFlickerMs`，从挨打算起 `hurtInvulnMs` 里无敌。心扣光才走原来的死亡流程。**被压、被埋、被箱子砸**还是直接死（`ctx.die`，人卡在里面出不来）。复活、R、换层心都回满。吃豆人层不用生命值（碰到就死，也不显示心）。手机端心固定 26 像素、让开刘海。

## 复活动画

玩家每次出现在地图上（开局、换层、复活、按 R、进入下一关），都由一只骷髅手从房间外斜着伸进来，捏着玩家放到复活点，停一下松手，脚下炸一圈紫色火花，然后缩回去（`game/core/respawnHand.ts`）。复活点在房间左半边就从左上角伸进来，在右半边就从右上角（贴图左右翻转）。手周围有紫色光雾，手臂末端是一团暗紫色烟雾，像从裂隙里伸出来。动画期间人冻着：不响应按键和 R，也不会死。

- 时长：`config.respawnHandMs`（默认 2000 毫秒，0 = 全都不播，直接出现）。四段比例（伸进来 / 放下 / 停顿 / 缩回）在文件顶部的 `PHASE`。
- 哪些场合播：`config.respawnHandOn`，按场合开关，默认全开：开局（开始游戏 / 再来一次 / 试玩）`start`、换层 `floor`、死后复活 `death`、按 R 重置 `reset`、进入下一关 `level`（放下之后再长高）。
- 贴图：`hand_hold.png`（捏着）和 `hand_open.png`（松开），同样大小，手臂从贴图左上角伸进来。现在是 `npm run gen-art -- hand_hold.png hand_open.png` 生成的占位图（160×160）。换成手绘图时，把 `asset/index.ts` 里 `RESPAWN_HAND.pinch` 改成新图的捏合点（玩家身体中心放的位置，按宽高比例写）；光雾和烟雾的颜色也在那里。

## 第四面墙：按 R 重置时攥纸团

按 R 重置房间时（`config.resetCrumple`，默认开；关了就是原来的直接重置）：骷髅手从屏幕左边伸进来，手心朝着玩家，一把攥住整个游戏画面，像纸一样揉成一团，往回一收、甩手扔出画面右边；重置好的房间淡入，淡入完骷髅手再把人放下来（和平时的复活动画一样）。

- 流程（要无缝）：`GameScene.requestRoomReset` → `crumpleWorld(after, grab?)`（`grab` = 攥住的位置，画面的比例坐标，默认正中）发 `EVT.crumple`：
  1. 游戏照常跑（能操作、音乐继续），手先伸到正在进行的画面上，左上角位置这类界面淡出（它们不在游戏画布里，攥不进纸团）；
  2. 手碰到画面时特效发 `EVT.crumpleFreeze`：场景暂停、声音停，等下一帧画完发回 `EVT.crumpleFrozen`；
  3. 3D 舞台上的屏幕在同一帧换成摆在原位的「纸」（和冻住的画面一样，看不出切换），然后攥拳、揉、捏紧、蓄力、甩出去；
  4. 纸团飞出画面后发 `EVT.crumpleDone`（带淡入时长 `fadeMs`）：场景恢复，调 `after(fadeMs)` 重置房间；人（连同帽子、手上的东西）先藏着，新房间在舞台上淡入，`fadeMs` 之后骷髅手再把人放进来。
  - 没挂特效层时 `crumpleWorld` 返回 false，直接重置；没有 WebGL（舞台起不来）时特效层直接回「放完了」。编辑器试玩里也挂着特效层和舞台。
- 时间线、手、声音在 `ui/crumple/`（`CrumpleOverlay`，挂在 `GameView` 和编辑器试玩里）；纸在 3D 舞台上（`stage3d/fx/crumple/`），每帧把纸的状态交给它画：
  - `crumpleMesh.ts`：纯几何，有单元测试。纸分成一片片，每片揉的时候各自转、缩、歪，片与片之间折出折痕；再叠两层 Voronoi「金字塔」细褶子；从捏住点由近到远包到拳心的球上，球面坑洼里压暗、棱上墨裂开露出白纸；纸翻过去的面画成纸背面；扔出去时整团转、翻、缩（`spin / tumble / ballScale`）。手感参数在文件顶部的 `TUNE`。
  - `CrumplePaper.ts`：把屏幕换成纸，按上面算好的三角形画（深度测试 + 每个三角形单独的明暗，纸背面和墨裂开的地方是白纸）。纸挂在屏幕上，屏幕倒着纸也跟着倒。
  - `crumpleSound.ts`：揉纸声、攥住那一下、手伸进来 / 甩出去的风声，全用 WebAudio 合成，没有音频文件。
  - `CrumpleOverlay.tsx`：时间线（各段时长在 `DUR`，松手时机 `RELEASE`）、手的位置 / 帧 / 影子 / 紫光、蓄力和甩的路线（`HAND.windup / swing`）、纸团飞走的弧线和转速（`FLY`）、画面震动。
  - 手：`grab_hand.png`，6 帧横排、从张开攥成拳头（`npm run gen-art -- grab_hand.png` 生成，手指按关节角度一节节卷起来）。手心朝镜头、拇指朝上、四指朝右，从左边水平伸进来，拳心对准攥住的地方；放大到手臂末端出了画面左边，拳头比纸团小一圈（`HAND.fistToBall`），揉皱的纸从指缝和拳头四周鼓出来；松手时倒着放回张开。换成手绘图时改 `asset/index.ts` 的 `GRAB_HAND`（帧数、帧大小、拳心位置、拳头高度）。
- 调试（开发版）：控制台 `__crumpleDebug = { speed: 0.2 }` 慢放，`{ at: 2000 }` 停在第 2000 毫秒，删掉这个变量恢复正常。

## 玩家大小与爆炸强度

`game/config.ts` 里的 `playerWidth` / `playerHeight`（单位：格，1 = 一格高）决定玩家贴图大小，默认 0.94 × 0.94 格（主角是一格见方的方块）。碰撞框高 = 贴图高，比一格矮一点，所以能钻过一格高的缝（正好 1 格会贴着天花板卡住）；碰撞框宽是 `playerHitboxWidth`（默认 0.75 格，居中），比贴图窄，走到一格宽的洞上更容易掉下去。`explosionRadius`（格）是起跳爆炸的强度。编辑器「游戏设置」里可以临时改身高和爆炸半径，下次试玩生效，不会存下来；要改默认值就改 config。

## 编辑器

左键画、右键擦、按住拖动连续画。**撤销 / 重做**：Ctrl(⌘)+Z、Ctrl(⌘)+Shift+Z（或 Ctrl+Y），层标签栏右边也有按钮。按下到松开画的一整笔算一步，侧栏连续打字算一步；改房间尺寸、加删房间 / 层、清空房间、载入 / 导入地图都能撤销。最多 100 步，只在这次打开的页面里有，刷新就没了。房间面板里「清空房间」把当前房间变回四周岩石的空房间（物件、引线、迷雾区、门、钥匙、文字都删掉），房间位置不变。

### 试玩

编辑器右边栏从上到下是「试玩」「房间」「文件」。试玩（`ui/editor/PlayPanel.tsx`）先设角色的起始状态：第几关的身高（第 1 / 2 / 3 关 = `stage` 0 / 1 / 2）、戴不戴帽子、手上拿什么（空手、蜡烛等道具、这一层有的某一组钥匙）。起始状态记在本地。

- 「从这层开始」：进入选点，编辑器地图上出现绿框，点一格就从那一格开始（实心的格子不行）；也可以点「从出生点开始」，ESC 或「取消」退出选点。
- 试玩中这里变成「返回编辑器」（和 ESC 一样）。死亡、「再来一次」都回到这次的起点。
- 这一层没有出生点（物件 `P`）时，「从出生点开始」不能点，面板里会提示。

### 文字关卡和自动试玩

- **文字关卡**（`levels/*.txt`，格式和量出来的跳跃数据见 `levels/README.md`）：一个文本文件画一整层，砖块、物件、钥匙、门画在同一张字符画里。`npm run level -- levels/floor2.txt` 检查，加 `--write` 写进 world.json（同 id 的层替换，别的层不动），然后编辑器里「载入」。第二层「钥匙井」（`levels/floor2.txt`，层 id `claude2`）、第三层「铸造厂」（`levels/floor3.txt`，`claude3`）、第四层「传送带」（`levels/floor4.txt`，`claude4`）、第五层「造纸坊」（`levels/floor5.txt`，`claude5`）和第六层「引线工坊」（`levels/floor6.txt`，`claude6`）就是这么做的，设计思路写在各自文件开头。
- **自动试玩**（`src/dev/bot.ts`，只在开发模式）：控制台里 `__climb.bot` 是一个程序控制的玩家。游戏循环改成一帧帧手动走，页面在后台也能跑；输入走模拟手柄。`await __climb.bot.load({ level: 'levels/floor2.txt' })` 直接编译文字关卡开始玩（也可以 `floor: 'f2'` 读 world.json 里的某一层，`room` / `at` 指定起点）；`bot.run('to 15; jump; wait 60; view')` 执行一串动作，`bot.view()` 把当前房间画成字符画（`P` 自己、`M` 怪物、数字是地上的钥匙、`!@$^` 是门）。命令列表是 `bot.COMMANDS`。骷髅手放人和 R 的攥纸团靠真实时间，load 时关掉。

## 操作

| 键盘 | 手柄 | 动作 |
| --- | --- | --- |
| ← → / A D | 左摇杆 / 十字键 | 移动 |
| ↓ / S | 左摇杆 / 十字键往下 | 摘帽子 |
| 空格 / ↑ / W | A（PS：✕） | 起跳（起跳点爆炸）、推进对话；吃豆人层只有空格 / A 放炸弹，↑ / W 和摇杆往上只是移动 |
| 贴墙下滑时按跳 | 贴墙下滑时按 A | 蹬墙跳（墙面爆炸） |
| R | Y（PS：△） | 重置当前房间（先放攥纸团特效，见「第四面墙」；换层的旋涡、长大、特效的过程中不响应） |
| ESC | Back / Select | 试玩时回编辑器 |
| 空格 / 回车 | A / Start | 标题画面开始游戏 |

**手柄**：用浏览器的 Gamepad API 标准布局（Xbox、PS 按钮位置一样），默认映射在 `game/gamepad.ts` 的 `GAMEPAD_BUTTONS`（按钮编号），改键就改这张表；摇杆推过 `STICK_DEADZONE` 才算。浏览器要等页面打开后按一下手柄上的键才认得出手柄。"往下按一下"（摘帽子）键盘、手柄、触屏都走同一个场景事件 `INPUT_DOWN`（`game/input.ts`）。

**R 重置房间的规则**：按材料的来源算，不按它现在在哪。地形每格记着"这块材料原本在哪一格"：这个房间的沙土、碎块掉到了别的房间，重置时一起收回来；别的房间的材料落在这个房间里，重置时放回它原来的位置（原位空着才放）。别的房间里正在掉的碎块、被怪物驮着的纸照常进行；正在烧的引线和一跳跳往下烧的连锁则整张图一起停。**死了之后重置什么**看 `config.deathReset`（编辑器左边栏「游戏设置 → 死了之后」可以切）：默认 `none` 什么都不重置，解过的就算解过了（炸掉的砖、烧过的引线、开过的门、推过的箱子、打死的怪都保持原样，手上的东西也还在），人回到这个房间的入口、心回满（`Respawn.revive`），卡关了就按 R 重置这个房间；例外是机制的 `resetsRoomOnDeath` 说要重开的——Boss 战打到一半死了、吃豆人层被抓到，还是重置当前房间。`room` = 死了重置当前房间；`world` = 死了、按 R 都重置整张图，所有东西都复原。
