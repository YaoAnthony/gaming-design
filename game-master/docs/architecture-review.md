# 架构审查（2026-10-05）

审查范围：`game-master/` 全部代码（约 2.1 万行）。看了五个方面：大文件和性能、文件分类、重复建设、存档（含 Steam 云存档、Electron）、以后每张图都有背景行不行。

审查之后直接改掉了大部分问题，每一步都跑了类型检查、ESLint、全部测试和打包，能在浏览器里看到的都实际玩过一遍。测试从 222 个增加到 279 个，全部放在 `tests/` 里。

## 一、已经改掉的

### 存档、Steam 云存档、Electron

审查时的情况：

- 没有 Electron，也没有任何 Steam 相关的东西。
- 所有东西塞在 `localStorage['climb:v1']` 一个 key 里：玩家的进度（几百字节）和编辑器的整个项目（约 84KB）混在一起。
- 每次换房间（检查点）都会把 84KB 的项目重新序列化写一遍。线上版本其实根本用不到编辑器的项目。
- 线上版本更新地图后，玩家的进度会被整份作废。
- 存储直接写死在 localStorage 上，换成桌面版写文件要改 Redux 层。

改成：

- `src/platform/`：存储后端。网页版用 localStorage，桌面版通过 Electron 的 preload 写文件。`redux/persist.ts` 只管存什么，不管存在哪。
- 分成两份：
  - `save`：进度 + 语言 + 音量，几百字节，桌面版同步到 Steam 云。
  - `editor`：编辑器工作区，只在开发版读写。
- 两份各自带格式版本，读的时候逐个字段检查，坏档不会让游戏起不来。
- 地图更新后进度保留，只是从那一层的出生点开始。
- 旧的 `climb:v1` 第一次打开时自动拆成两份。
- 关页面前（`pagehide`）把还没写的马上写掉。
- `electron/`：
  - 主进程用 `app://` 协议加载打包好的网页，不用改 Vite 的 base。
  - 开了 sandbox 和 contextIsolation。
  - F11 全屏，不让网页打开新窗口。
  - 存档原子写入：先写 `.tmp` 再改名，留一份 `.bak`；主文件坏了自动读 `.bak`。
  - 标题页在桌面版多一个「退出」。
- `docs/desktop.md`：怎么跑桌面版，以及 Steam 后台的自动云同步（Auto-Cloud）怎么填。只同步 `save.json`，不用接 SDK。

### 性能

| 问题 | 频率 | 改法 |
| --- | --- | --- |
| 跳跃预览每帧重算连锁、松脱并重画 | 每帧 | 给地形和迷雾加版本号，起跳点、地形、已知区域没变就不重算 |
| 每次爆炸把整张地图的体积感重算一遍（最大一层九千多格） | 每次爆炸、引线跳、碎块落地、方块移动 | 只重算改动附近的一块；测试里和整图重算逐格比对，结果一致 |
| 换层 / 重开时迷雾和体积感的画布贴图没释放 | 每次换层 | 场景关闭时释放 |
| 节奏关卡每个音符让整个 HUD 重渲染三次 | 每个音符 | HUD 拆成小组件，各自只订自己那一块；血条只在血变了时才派发 |
| 每次判定都把整张谱的音符数一遍、每帧多次重算谱面分段 | 每个音符 / 每帧 | 按场、按谱面缓存 |
| 开发期 Redux 检查每次派发都遍历 84KB 的项目 | 每次派发（开发版） | 跳过项目（编辑器的 reducer 都走 Immer） |
| 碎块下落时每块对每块逐格比较（平方级） | 碎块下落时每帧 | 改用「格子 → 碎块」表 |
| 碎块接触检测每格 new 一个 Rectangle | 碎块下落时每帧 | 换成不建对象的判定；测试里和 Phaser 原版逐个比对 |
| 移动方块每帧多次拼字符串集合 | 每帧 | 按位置缓存占着的格子，用数字 key |
| 节奏大师不在场时还在重画拍线 | 每帧 | 不在场就跳过 |

### 重复建设

- **四套合成音**：打击音、节拍器、捏纸团各开一个 AudioContext，也不受游戏的静音和总音量控制。现在共用 `src/audio/synth.ts` 的一个出口，接在 Phaser 的总线上。Boss 的「滴」从史莱姆王的文件夹移到 `src/audio/`，节奏关卡不再跨机制引用它。
- **节奏关卡的按键提示**：表移进 `rhythm/modes.ts` 的 `hints`，HUD 从那里读。新增测试：每种玩法都要有实现、提示、两种语言的文案和谱面录制的键位，漏一样就报错。
- **语言列表**：`i18n/langs.ts` 一份，存档校验和标题页的切换都从它来，不再写死 `zh` / `en`。

### 文件分类

- 测试全部移到 `tests/`，目录和 `src/` 一一对应。Phaser 替身在 `tests/support/`。
- 调色板、触屏输入、手柄映射是两边都用的，原来放在 Phaser 的文件夹 `game/` 里，3D 一侧要从 `game/` 引用。现在移到 `src/shared/`，3D 一侧被 ESLint 禁止引用任何 `@/game/*`。
- 画面层次（depth）原来是散落各处的数字，现在新建 `game/depth.ts` 集中定义，背景相关的层和节奏关卡已经用上。
- 角色名统一成 Game Master：i18n 的 key 改成 `npc.gameMaster`，注释和文档里的「骷髅王」都改了。
- `window.__climb` 等调试口子写了全局类型（`src/dev/globals.d.ts`），去掉了 `as unknown as` 强转。

### 顺手修掉的 bug

- 节奏关卡开场白说到一半时切走（换页签、关游戏），清理代码去碰已经被拆掉的玩家，整页黑屏。
- 画面矮的时候，判定字「MISS」压在 Boss 名字上。
- 几处和代码对不上的注释，例如「进入下一关会长大」。

## 二、第 3 项：每张图都有背景

审查结论：原来只有一张写死的渐变天空 + 星星，整层共用；没有数据字段、没有按需加载、没有视差，所以需要新做。

现在已经做好：

- **背景清单** `asset/backgrounds.ts`：
  - 一个背景可以叠几层图，从远到近，每层有视差。
  - 图放在 `src/asset/backgrounds/`，不进启动时的加载清单。
- **地图字段**：`Floor.background` 是每层的默认背景，`WorldModel.roomBackgrounds` 让房间单独换。认不出的 id 退回星空，不会让那一层起不来。
- **游戏里**（`game/background/Backdrop.ts`）：
  - 进到这一层才加载背景图，加载完之前先显示星空；换层时把用不到的放掉。
  - 每个房间各放一套、裁到房间大小。平移时相邻两个房间各显示各的，只有看得到的房间才显示。
  - 背景画进游戏画布，3D 屏幕和攥纸团都会带上它。
- **编辑器**：层设置和房间面板都有「背景」下拉，画布里直接预览当前房间的背景，可以撤销。
- **文字关卡**：`background <id>`、`roombg <房间> <id>`。
- **占位图**：洞穴、黄昏两套，各两层（`npm run gen-art -- backgrounds`）。现在所有层都还是默认的星空，没有替你改任何关卡的样子。

以后换成真的美术：图放进 `src/asset/backgrounds/`，清单里加一项（或者改现有那项的文件名）。

- 每层的 `parallax` 越大，人走动时那层挪得越多，适合近处的层。
- 像素风的图写 `pixelated: true`，放大时不会糊。

## 三、检查过、没问题的

- three.js 舞台只在特效进行中才渲染、才上传画布贴图；几何体、材质、贴图都有释放。
- 事件监听（bridge、键盘、手柄、场景事件、React effect）都成对解除。
- 迷雾只在需要时重算、重画；光照扩散限制在半径附近。
- 平时的平台跳没有每帧的 Redux 派发。
- 对话的打字机效果用 motion value，不是每个字一次 React 渲染。

## 四、还没改、建议之后做的

按价值从高到低排。工作量 S / M / L 分别指半天以内、一两天、更多。

前四条已在后续的提交里做完（见第六节），下面从第 5 条接着列。

5. **3D 关卡没有选择入口**：跳出画面永远进 `FIRST_LEVEL`。等有第二个 3D 关卡时，需要从层或房间指向关卡。
6. **停放着的代码**：`Growth.begin`（长大仪式，现在没人调用）、`WALL_TEXTURES`（墙的拼贴）、`FogState`（迷雾记忆的存档）。这几样像是留着以后用的，所以没删；如果确定不要了可以清掉。
7. **桌面版发布**：还没有打包成安装包（electron-builder 或 electron-forge），也没有接 Steamworks SDK（成就、Overlay 才需要）。云存档按 `docs/desktop.md` 配置就能用，不需要 SDK。
8. **剩下的小性能项**：
   - 攥纸团时每帧改两层 CSS 阴影滤镜（约 2 秒）。
   - 史莱姆王的黏液每帧拆字符串、filter 数组。
   - 攥纸团的手每帧新建 Vector3。
   都只在特定时刻发生，影响小。
9. **音量放在游戏参数 `config` 里，语言放在 `settings` 里**：这是有意保留的。游戏里的滑块机关直接绑定 `config` 的字段，挪走会破坏这个机制。存档层已经把两者合在玩家存档里一起存。
10. **旧格式兼容代码**（`normalizeModel` 里的字符替换、`roomFlags.boss`、`topdown` 别名）：打包的地图已经不用了，只为旧的本地存档保留，可以在下个大版本删掉。

## 五、注意

- 自动化测试过程中，我在你的浏览器里点过「New game」和 B，所以你本地开发版的进度被重置到了第一层。其他层的编辑都已撤销还原，编辑器工作区和原来一样。
- 桌面版没有实际打开窗口验证（启动 Electron 窗口的命令被权限拦下了）。主进程和 preload 做了语法检查，存档文件的读写有单元测试；网页这一侧的存档在浏览器里实测过。第一次在本机跑 `npm run desktop` 时，请看一下窗口能否正常打开、存档是否写进了 `~/Library/Application Support/Game Master/save/save.json`。

## 六、后续：三项大的重构（2026-10-06）

1. **换层 / 存档带走的状态按机制 id 存**（原第 3 条）
   - `Mechanic.persist()` 返回这个机制自己的数据，存在 `carry[机制 id]` 下；进层时机制用 `ctx.carried(id)` 拿回来，自己校验。
   - 存档升到第 2 版，第 1 版（帽子、道具是单独的字段）读进来自动转换。
   - 新机制要带东西过层、进存档：场景、协议、存档读取都不用改。
2. **节奏关卡是一个通用机制**（原第 2 条）
   - 文件夹从 `game/rhythm/` 搬到 `game/mechanics/rhythm/`，机制 id 是 `rhythm`，每一层都启用。它自己听「开一场」，场地不是这一层就先传过去。
   - 新的 `Mechanic.takesControl()` 钩子：机制接管按键时，场景不让人走、不响应跳和 R。`GameScene` 里不再有节奏关卡专门的代码（538 行 → 501 行）。
   - 开场台词放进谱面数据（`chart.intro`）。
   - 「这一层有没有心」由层机制自己声明（`hearts: true`），不再在场景里认 `platform` 这个 id。
3. **地图图层和编辑器工具都改成登记**（原第 1、4 条）
   - **数据**：`game/world/layers.ts` 登记按房间存的数据。引线、迷雾区、移动标记、门、钥匙、物件、文字、房间开关、背景都在各自的文件夹里登记；删房间、清空、改尺寸都遍历登记表。锁和文字的辅助函数搬回各自的机制文件夹，`WorldModel.ts` 从 429 行降到 252 行。
   - **编辑器**：`game/editor/tools.ts` 登记画笔，内容包括物品栏那一组、画一格派发什么、画布上怎么叠加。`EditorScene` 从 421 行降到 291 行，物品栏只遍历登记表；编辑器的六个分层画格 reducer 合并成通用的 `paintLayer` / `paintLayerRect`。
   - **关卡脚本**：新增测试拿注册表核对文字关卡脚本里手抄的字符表。第一次跑就查出脚本漏了音量滑块 `V`，还把王之炸药 `E` 当成了不挡人、不能放移动方块，已修。
   - **验证**：重构前先按旧代码写了特征测试，重构后结果一致。编辑器里每种画笔、添加 / 删除组的确认、撤销都在浏览器里实际点过；七层地图都能正常进。
